# Capability contracts — proposed

`capabilities.json` names the boundaries the future client SDK and runtime will implement. Requests obtain subject/organization context from a validated session, not trusted patient identifiers in a browser payload.

A proposal binds exact booking details and expiry. Confirmation represents an authenticated patient action on that proposal. A model-provided flag is not sufficient. Unknown write outcomes remain pending reconciliation. Version contracts and run consumer checks before upgrades.

These descriptors are not an OpenAPI server definition and do not imply implemented endpoints.
